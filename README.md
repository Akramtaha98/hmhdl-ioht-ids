# Supplementary Materials
## A Split-Aware Evaluation of Lionfish-Tuned Hybrid Deep Learning for
## Internet of Health Things Intrusion Detection

This archive accompanies the manuscript submitted to MDPI Journal of
Cybersecurity and Privacy. It contains the full preprocessing, modeling,
optimization, baseline, ablation, identifier-removal, repeated-seed, and
sensitivity-analysis code, the random seeds and exact train/test split
indices (main split and every alternative split), and all raw result files
(JSON) underlying every table and figure in the manuscript.

## Directory layout

All code reads and writes relative to the project root (the parent of
`code/`), so the archive can be unzipped anywhere:

```
supplementary/
  code/           all Python scripts (see below)
  data/           place the three raw dataset CSVs here (not redistributed
                  in this archive; see "Datasets" below)
  results/        every raw result JSON file (included)
  split_indices/  exact row indices for the main split and every
                  alternative split (included)
  figures/        regenerated by code/make_figures.py (not included; run
                  the script to produce them)
  checkpoints/    regenerated automatically by every staged/checkpointed
                  script (not included; these are large, resumable
                  intermediate model/optimizer state files)
  requirements.txt
  run_all.sh      orchestrates the full pipeline end to end
```

## Contents of `code/`

- `pipeline.py` — dataset loaders, split-before-fit preprocessing, the
  CNN-LSTM-GRU-Attention model builder, the Lionfish Optimization
  Algorithm, and the staged/checkpointed train+evaluate pipeline used to
  produce the main results (Section 4).
- `baselines_and_metrics.py` — same-split classical ML baselines (logistic
  regression, random forest, histogram gradient boosting, MLP), extra
  probability-based test metrics (ROC-AUC, PR-AUC, per-class
  precision/recall/F1, specificity, false-negative rate) for the final
  hybrid model, and the same probability-based metrics for every classical
  baseline (`baseline_extra` mode; addresses Section 4.6's gradient-boosting
  comparison on WUSTL-EHMS-2020).
- `search_comparison.py` — the random-search baseline (matched budget to
  Lionfish) and the architecture ablation screen (CNN-only, CNN-LSTM,
  CNN-GRU, CNN-LSTM-GRU, full hybrid, full hybrid with default
  hyperparameters).
- `sensitivity_split.py` — version 1 of the temporal (ECU-IoHT,
  WUSTL-EHMS-2020) and flow-grouped (DSICU) alternative-split robustness
  checks: reuses the main split's Lionfish-selected hyperparameters and
  keeps the split-defining field as a model feature. Kept for
  transparency/comparison; superseded by version 2 below.
- `no_identifier_check.py` — re-runs the MAIN (random) split with the
  capture-order/identifier-like field (`Time`, `Packet_num`, or
  `tcp.srcport`/`tcp.dstport`) excluded from the model's input features,
  isolating that field's contribution independent of any split choice
  (Section 4.9).
- `sensitivity_split_v2.py` — the revised alternative-split sensitivity
  analysis: hyperparameters are found by an independent random search
  restricted to each alternative split's own training partition only
  (`search` stage, 42 candidates — matched to the main Lionfish/random-
  search budget), and the identifier-like field is excluded from the
  feature set entirely; the final model (`train` stage) is trained for up
  to 80 epochs with patience 8, identical to the main experiment's
  training budget. This is the version reported as "v2" throughout
  Section 4.9/5.4, and is budget-matched to the main experiment in every
  respect except the split itself.
- `repeated_seeds.py` — trains the final model on the main split's
  train/test partition with three additional seeds (43, 44, 45) under the
  exact same budget as the original seed 42 (up to 80 epochs, patience 8),
  and summarizes all four runs (including the original seed 42 from
  `results/*_results.json`) as mean ± standard deviation (Section 4.3).
- `export_split_indices.py` — regenerates the exact row indices used for
  the main train/test split and every alternative split (deterministic
  given the fixed seeds; indices are also provided directly in
  `split_indices/` so this does not need to be re-run to verify).
- `make_figures.py` — regenerates every figure in the manuscript from the
  result JSON files at 600 DPI.
- `references.py` — the manuscript's numbered reference database.
- `build_manuscript_mdpi_template.py` — the script that assembles the full
  manuscript (all text, tables, and figure placements, including every
  numeric value quoted above) inside MDPI's official JCP Word template.
  Included for transparency, not intended for reviewers to re-run: it
  requires MDPI's `jcp-template.dot`, which is not redistributed here for
  licensing reasons.

## Contents of `split_indices/`

- `{Dataset}_train_indices.csv` / `{Dataset}_test_indices.csv` — 0-indexed
  row indices into the raw CSV (as loaded by `pipeline.LOADERS`) for the
  MAIN random stratified split reported in Section 4.
- `{Dataset}_altsplit_train_indices.csv` / `..._altsplit_test_indices.csv`
  — original-CSV row indices for each dataset's ALTERNATIVE split used in
  Section 4.9 (temporal order for ECU-IoHT/WUSTL-EHMS-2020, port-pair
  group assignment for DSICU).

## Random seeds

A single fixed random seed (42) is used throughout the main experiment:
NumPy, TensorFlow, and every scikit-learn splitting/estimator call. The
random-search comparison (Table 10) uses a distinct, separately seeded
stream (42 + 999). The version-2 alternative-split hyperparameter search
(`sensitivity_split_v2.py`) uses yet another distinct stream (42 + 4242),
so it does not silently reuse either of the other two draws. Repeated-seed
runs (Section 4.3) use seeds 43, 44, and 45 in addition to the original 42.

## Environment

Python 3.10. See `requirements.txt` for exact package versions (also
listed here): TensorFlow/Keras 2.15.0, scikit-learn 1.7.2, NumPy 1.26.4,
pandas 2.3.3, matplotlib 3.10.9, python-docx 1.2.0 (only needed to rebuild
the manuscript .docx, not for reproducing results). Install with:

```
pip install -r requirements.txt
```

All experiments were run on CPU only (no GPU acceleration).

## Running everything

```
cd supplementary/
# place the three raw CSVs in data/ first (see Datasets above)
bash run_all.sh
```

`run_all.sh` runs every stage in the correct order and automatically
retries any stage that reports a time-budget checkpoint rather than
completion (each stage is independently resumable). See the comments
inside `run_all.sh` for expected running time and a stage-by-stage
breakdown.
